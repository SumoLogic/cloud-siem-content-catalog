# [Rules](README.md): Spike in HTTP Server Errors from Source IP

## Description
Detection: This rule detects a statistically significant spike in HTTP 5xx server error responses generated by a single source IP against known web servers, relative to that IP's own 30-day historical baseline.

Scenario: A sudden spike in server-side errors triggered by one source against web infrastructure often indicates exploitation attempts (e.g. malformed requests crashing an application), automated fuzzing, or a client repeatedly hitting a broken endpoint.

Requirements: The web_servers and/or http_servers match lists must be populated with the hostnames of the web servers to monitor, and HTTP access logs from those servers (for example Apache, nginx or IIS) must be ingested with the HTTP response status code normalized. If both lists are empty, this rule will not fire.

Recommended Actions: Review the source IP's request pattern -- URLs, user agents, and targeted hosts. Check whether requests span many distinct web servers (broad exploitation attempt) or concentrate on one (targeted attack on a specific service).

Tuning Recommendations: Scoped to the web_servers and http_servers match lists so only known web server traffic is evaluated. Authorized vulnerability scanners are excluded via the vuln_scanners match list.
